# ML Iris Production

Учебный ML-проект для классификации цветов ириса на основе классического датасета Iris.

Проект демонстрирует базовые практики подготовки Python/ML-кода к production-использованию:

- модульная структура исходного кода;
- разделение обучения модели и инференса;
- воспроизводимая установка зависимостей через Poetry;
- локальное виртуальное окружение `.venv`;
- статический анализ, форматирование и проверка типов;
- автоматические проверки перед коммитом и push через pre-commit;
- unit-тесты.

## Задача

Модель получает четыре числовых признака цветка и определяет один из трёх классов:

- `0` — setosa;
- `1` — versicolor;
- `2` — virginica.

Используемые признаки:

- длина чашелистика — `sepal length`;
- ширина чашелистика — `sepal width`;
- длина лепестка — `petal length`;
- ширина лепестка — `petal width`.

## Установка

### Требования

Перед началом работы должны быть установлены:

- Python 3.12;
- Poetry 2.x;
- Git.

Проверка версий:

```powershell
py --version
poetry --version
git --version
```

### Клонирование проекта

```powershell
git clone https://github.com/perfectInt/ml-iris-production.git
cd ml-iris-production
```

### Создание окружения и установка зависимостей

Poetry создаёт изолированное окружение внутри проекта в каталоге `.venv`.

```powershell
poetry config virtualenvs.in-project true
poetry env use 3.12
poetry install --with dev
```

После установки зависимости будут находиться в `.venv/`.

> Каталог `.venv/` не хранится в Git, поскольку содержит локальные, платформозависимые исполняемые файлы и зависимости. Воспроизводимость окружения обеспечивают `pyproject.toml` и `poetry.lock`.

## Обучение модели

Запуск обучения:

```powershell
poetry run python -m iris_classifier.train
```

Во время выполнения скрипт:

1. Загружает датасет Iris из `scikit-learn`.
2. Делит данные на обучающую и тестовую выборки.
3. Обучает `RandomForestClassifier` в составе `Pipeline`.
4. Вычисляет accuracy на тестовой выборке.
5. Сохраняет обученную модель в `models/iris_classifier.joblib`.

Пример ожидаемого вывода:

```text
INFO | Модель сохранена: ...\models\iris_classifier.joblib
INFO | Accuracy на тестовой выборке: 0.9000
```

Точная метрика может незначительно отличаться при изменении версий библиотек или параметров модели.

## Предсказание

Сначала обучаем модель, затем передаем признаки цветка:

```powershell
poetry run python -m iris_classifier.predict `
  --sepal-length 5.1 `
  --sepal-width 3.5 `
  --petal-length 1.4 `
  --petal-width 0.2
```

Пример результата:

```text
Предсказанный класс: 0
```

Соответствие классов:

| Код | Класс ириса |
|---:|---|
| 0 | Iris setosa |
| 1 | Iris versicolor |
| 2 | Iris virginica |

## Pre-commit

Перед коммитом автоматически выполняются:

- проверка YAML и TOML-конфигураций;
- удаление лишних пробелов;
- добавление завершающего перевода строки в файлы;
- проверка конфликтных маркеров Git;
- проверка на случайно добавленные крупные файлы;
- обнаружение приватных ключей;
- линтинг и форматирование Ruff;
- проверка конфигурации Poetry;
- запуск тестов перед отправкой изменений в удалённый репозиторий.

Установка Git-хуков:

```powershell
poetry run pre-commit install
poetry run pre-commit install --hook-type pre-push
```

## Работа с Git и окружением

В репозиторий добавляются:

```text
src/
tests/
pyproject.toml
poetry.lock
.pre-commit-config.yaml
.gitignore
README.md
```

Не добавляются:

```text
.venv/
__pycache__/
.pytest_cache/
.mypy_cache/
.ruff_cache/
models/*.joblib
.env
```

Для развёртывания проекта на другом компьютере достаточно клонировать репозиторий и выполнить:

```powershell
poetry install --with dev
```

Poetry создаст новое локальное окружение и установит зависимости в версиях, зафиксированных в `poetry.lock`.

## Production-практики

В рамках учебного проекта реализованы следующие production-практики:

| Практика | Реализация |
|---|---|
| Разделение ответственности | Код разделён на модули: данные, модель, обучение, инференс и конфигурация |
| Воспроизводимость | Зафиксированы зависимости в `poetry.lock`, используется `RANDOM_STATE = 42` |
| Изоляция зависимостей | Для проекта используется локальное виртуальное окружение Poetry `.venv` |
| Качество кода | Используются Ruff, mypy и единый стиль форматирования |
| Автоматизация контроля качества | Git-хуки pre-commit запускают проверки перед commit и push |
| Тестирование | Добавлены unit-тесты pytest |
| Управление артефактами | Обученная модель создаётся в `models/` и исключена из Git |
| Конфигурация | Пути к артефактам и параметры обучения вынесены в `config.py` |
